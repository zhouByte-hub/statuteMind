# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

delegated: 单文件 HTML/CSS/JS 原型界面（用户明确表示"只需要先生成一个原型界面"，无需后端；AI 能力用模拟数据呈现，预留 OpenAI 兼容接口接入位）

## Users

主要用户：需要快速查法、判断行为后果的普通人与初级法务/HR/合规从业者。场景：遇到或目睹某个行为（如"公司拖欠工资""网上骂人"），想知道可能违反哪些法律、有什么后果、风险多大。任务是"搜法条"与"判行为"两类。

## Product Purpose

法律法规搜索引擎 Agent 原型（产品名 statuteMind，取自项目目录名，未与用户确认）：一是像 RAG 一样检索法律法规知识库并给出带出处的条文结果；二是对描述的违法行为作出法律判断，输出"引用条文 + 违法定性 + 处罚/责任 + 风险提示"四段结构。成功标准：原型界面完整可演示、动画丰富、判断结果结构清晰可信。

## Positioning

不只是法条全文检索，而是"行为 → 法律后果"的判断引擎：把生活语言翻译成法律语言并给出定性与风险提示。

## Operating Context

本地浏览器直接打开单文件演示；无后端、无真实 LLM（暂无 API Key），检索与判断结果由内置模拟数据驱动；法条数据为内置精选库（宪法、刑法、民法典、劳动法、治安管理处罚法等核心条文），界面含"上传导入"入口（原型中为模拟流程）。

## Capabilities and Constraints

- 内置精选法条库（模拟 RAG 检索：关键词/语义匹配演示）
- 违法行为判断：输出引用条文、违法定性、处罚/责任说明、风险提示
- 支持上传文档扩充知识库（原型中模拟处理流程）
- 无真实 LLM 后端；所有 AI 推理为前端模拟，需预留未来接入位
- 界面需丰富的动画效果（用户明确要求）

## Brand Commitments

- 名称：statuteMind（源自目录名，待确认）
- 用户明确要求"丰富的动画效果"为产品体验的一部分
- 上一版原型（5x5 书架 + 箱猫找书动画）用户认为样式不佳，不作为视觉权威

## Evidence on Hand

无真实法条数据文件；原型中的法条内容需按公开法律的常识性条文编写，并在界面标注"演示数据"。

## Product Principles

1. 判断先于检索：用户带着"这事违法吗"来，条文是证据不是终点。
2. 出处可查：每个结论都能落到具体法条原文。
3. 动画服务理解：动画用于呈现检索/推理过程，不喧宾夺主。
4. 免责透明：AI 判断必须明示"仅供参考，不构成法律意见"。

## Accessibility & Inclusion

界面为中文；需保证键盘可达、动效尊重 prefers-reduced-motion。
